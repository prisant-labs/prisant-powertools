## Hygiene Gates

These conditions block tagging. `--gate` reports current pass/fail.

| Gate | Condition | Status |
|------|-----------|--------|
| (a) Spec status | Every effort's `spec.md` has `status: committed` or `fulfilled` (no `draft`) | N/A (no efforts yet) |
| (b) Coupled plan | Every effort has an `implementation-plan.md`, OR is in `gate-waivers` frontmatter | N/A |
| (c) AC coverage | Every `implementation-plan.md` has `ac-coverage: complete` | N/A |
| (d) Phases done | Every plan's completion table shows every phase `Done` | N/A |
| (e) Staleness | No `spec.md` edited after its sibling `implementation-plan.md`'s last edit | N/A |

(See `references/hygiene-gates.md` for the computation rules per gate.)

## Template notes

- **Folder structure:** the .md sits at `release-plans/plan_NN_<slug>/plan.md`. Per-effort subfolders are peers (siblings to the .md inside the folder).
- **Aggregation section is generated.** `--update` rewrites this section's table from the folder walk. Don't author the rows.
- **Hygiene gates section is partially generated.** The gate descriptions are static (template above); the `Status` column is updated by `--gate` (read-only) and by `--update` (incidental).
- **Doc-update checklist defaults are baked in** but the `release-checklist.yaml` adds project-specific rows on top. Per-release tweaks happen by hand-editing the table after `--create`.
- **Theme / Context / Notes sections are maintainer-authored.** `--update` does not touch them.

## What goes where, decision tree

```
Is this content about... ?
  - what's in scope (specs and plans)  -> Aggregation (generated, do not edit)
  - whether the release can ship       -> Hygiene Gates (status auto, descriptions static)
  - what docs need updating            -> Doc-Update Checklist (defaults + yaml extension)
  - why this release exists            -> Theme / Context (maintainer-authored)
  - decisions made about the release   -> Open Questions / Decisions (decisions-section standard)
  - the spec or plan itself            -> NOT HERE. Lives in the per-effort folder.
```
