# Review Document Template

This is the canonical template for ai-review output. `--review` mode generates the structure with placeholders. `--respond` mode fills in the synthesis sections.

Phase annotations: **[P2]** = generated by `--review`, **[P3]** = filled by reviewer, **[P4]** = filled by `--respond` (first pass - initial synthesis), **[P5]** = filled by JP (Maintainer Response and/or Clarification Request), **[P6]** = filled by `--respond` (second pass - clarification answers only).

**Frontmatter is the one exception to "the body below is the whole document."** A document generated by plain `--review` (no `--dispatch`) carries no frontmatter block at all - this is the overwhelming majority of reviews, and `scripts/frontmatter-check.py` skips a markdown file with none, exactly like any other frontmatter-free file under this repository. A document generated with `--dispatch`, or later collected with `--collect`, carries exactly this block, written by `scripts/dispatch.py` and never hand-edited:

```markdown
---
type: review
dispatch-job: task-mvaign5s-0pq15s
---
```

See `references/dispatch.md` for what writes it and when, and `docs/internal/schemas/review.schema.json` for its shape. No other frontmatter field exists for this document type (A-02 spec decision D2): the carve-out from this skill's Non-Goal on document format is exactly these two fields, nothing wider.

## Instructions for Reviewer

[P2: generated with anti-sycophancy instructions, source docs, finding format, severity defs]

**Your role:** Independent critical reviewer. Your job is to find problems,
inconsistencies, gaps, and risks. You are not here to validate - you are here
to pressure-test.

**Key principles:**
- Disagreement is more valuable than agreement
- If you find nothing wrong in a section, say so explicitly and explain WHY
- If you find nothing wrong anywhere, that's suspicious - look harder
- Rate your confidence - low-confidence concerns are still worth noting
- Cite specific evidence for every finding (section numbers, quotes, file paths)

**Source documents:**

| Document | Path | Role |
|----------|------|------|
| [Primary] | `[path]` | Document under review |
| [Supporting] | `[path]` | Referenced context (if applicable) |

**Finding format:**

- [Severity | Confidence] Description with evidence woven in.
  Source says "X" (Section N) but also says "Y" (Section M). → Recommendation.

**Severity definitions:**
- **Blocker** - Must resolve before proceeding. Will cause incorrect results or structural failure.
- **Major** - Should resolve before proceeding. Significant gap causing confusion or rework.
- **Minor** - Can defer. Real issue but won't prevent the work from succeeding.
- **Note** - Observation or suggestion. No action required but worth considering.
